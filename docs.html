1. Overview & General Specifications

This document serves as the formal technical documentation for the ReqRes REST API (https://reqres.in) and its accompanying automated regression test suite. ReqRes is a mock RESTful web service providing realistic responses for prototyping and QA test automation.

Key Architectural Principles

  • Protocol: HTTPS only (port 443).
  • Content Negotiation: All requests sending a body must include Content-Type: application/json. All responses return application/json; charset=utf-8.
  • Authentication: Mock token authentication returning session tokens for valid registered users.
  • Rate Limiting: Enforces throttling (HTTP 429) on public shared IP pools. Test scripts incorporate rate-limit resilience.

2. Complete API Endpoint Reference

Module 1: User Management (CRUD)

GET /api/users?page={page} 200 OK

Retrieves a paginated list of user records.

Query Parameters:
  • page (number, optional, default: 1): Page index
  • per_page (number, optional, default: 6): Items per page
Sample Response (200 OK): 
{
  "page": 1,
  "per_page": 6,
  "total": 12,
  "total_pages": 2,
  "data": [
    {
      "id": 1,
      "email": "george.bluth@reqres.in",
      "first_name": "George",
      "last_name": "Bluth",
      "avatar": "https://reqres.in/img/faces/1-image.jpg"
    }
  ]
}
GET /api/users/{id} 200 OK / 404 Not Found

Fetches full profile information for a specific user ID.

Path Parameters:
  • id (number, required): User ID (e.g., 2)
Response Codes:
  • 200 OK: Valid user record returned
  • 404 Not Found: Non-existent ID (returns {})
Sample Response (200 OK): 
{
  "data": {
    "id": 2,
    "email": "janet.weaver@reqres.in",
    "first_name": "Janet",
    "last_name": "Weaver",
    "avatar": "https://reqres.in/img/faces/2-image.jpg"
  },
  "support": {
    "url": "https://contentcaddy.io?utm_source=reqres&utm_medium=json&utm_campaign=referral",
    "text": "Tired of writing mock data?..."
  }
}
POST /api/users 201 Created

Creates a new user record and returns the allocated ID with timestamp.

Request Body (JSON): 
{
  "name": "Tanzim SQA",
  "job": "Lead QA Automation Engineer"
}
Sample Response (201 Created): 
{
  "name": "Tanzim SQA",
  "job": "Lead QA Automation Engineer",
  "id": "416",
  "createdAt": "2026-10-16T09:14:21.054Z"
}
PUT /api/users/{id} 200 OK

Performs a full replacement update on a user record.

Request Body (JSON): 
{
  "name": "Tanzim SQA - Updated",
  "job": "Principal QA Automation Architect"
}
Sample Response (200 OK): 
{
  "name": "Tanzim SQA - Updated",
  "job": "Principal QA Automation Architect",
  "updatedAt": "2026-10-16T09:14:22.100Z"
}
PATCH /api/users/{id} 200 OK

Performs a partial update (e.g. updating job title only).

Request Body (JSON): 
{
  "job": "Staff SDET"
}
Sample Response (200 OK): 
{
  "job": "Staff SDET",
  "updatedAt": "2026-10-16T09:14:23.010Z"
}
DELETE /api/users/{id} 204 No Content

Deletes an existing user record. Returns HTTP 204 with an empty response body.

Module 3: Authentication & Authorization

POST /api/register 200 OK / 400 Bad Request
Valid Request Body: 
{
  "email": "eve.holt@reqres.in",
  "password": "pistol"
}
Success Response (200 OK): 
{
  "id": 4,
  "token": "QpwL5tke4Pnpja7X4"
}
Missing Password Request: 
{
  "email": "sydney@fife"
}
Error Response (400 Bad Request): 
{
  "error": "Missing password"
}
POST /api/login 200 OK / 400 Bad Request
Valid Login Request: 
{
  "email": "eve.holt@reqres.in",
  "password": "cityslicka"
}
Success Response (200 OK): 
{
  "token": "QpwL5tke4Pnpja7X4"
}
Invalid Login Scenarios (400 Bad Request):
  • Missing password: {"error": "Missing password"}
  • Unregistered user: {"error": "user not found"}

Module 4: Performance & Network Latency

GET /api/users?delay={seconds} 200 OK

Simulates backend network latency by delaying response delivery by the requested duration in seconds. Tests client timeouts and payload preservation under latency.
